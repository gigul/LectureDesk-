# OpenAI processing and recovery

Production code lives in `src/main/ai-provider.ts` (HTTP/WebSocket adapter), `ai.ts` (durable orchestration and realtime windows), `ai-retrieval.ts` (local scoped FTS5 index), and `ai-logic.ts` (ordering, chunking, and retries). Decision logic for transcription is kept in pure, unit-tested modules: `audio-analysis.ts` (levels, `SilenceTracker`, `shouldCommit`, `cutAllowed`, `planChunks`), `transcript-coverage.ts` (`windowGaps`, `turnFrontier`, `ensureCoverage`), `transcript-language.ts` (`checkTranscript`) and `src/shared/transcript.ts` (`transcriptUnits`, `renderTranscript`, `segmentAt`, `turnPolicy`). `audio-range.ts` reads byte ranges of the recording from its WAV files. Only the Electron main process obtains the secure credential. Provider adapters can be replaced through `AIOptions`; fixture adapters exist only in automated tests.

## Official documentation checked on 3 October 2026

- [Model catalog](https://developers.openai.com/api/docs/models): `gpt-6.1-sol` balances quality and cost; the maximum quality preset uses `gpt-6-astra`.
- [Realtime transcription](https://developers.openai.com/api/docs/guides/realtime-transcription): `gpt-live-transcribe`, 24 kHz PCM, manual commits, transcript deltas/finals, plural `languages`, vocabulary `keywords`, and `delay: medium`. Turn detection is null for this model.
- [Realtime sessions](https://developers.openai.com/api/docs/guides/realtime-conversations): 60 minute lifetime; LectureDesk renews after 55 minutes at a speech-turn boundary (see the continuous-stream section below).
- [Realtime WebSockets](https://developers.openai.com/api/docs/guides/voice-websockets?api=realtime): main-process authenticated socket transport. Committed item IDs reconcile final transcript events that may finish in a different order.
- [File transcription](https://developers.openai.com/api/docs/guides/speech-to-text): `gpt-transcribe`, 25 MB file limit, supported audio formats and vocabulary/language context. Imports are converted to bounded WAV files. Whisper alone supports the requested provider timestamp granularities.
- [Responses text generation](https://developers.openai.com/api/docs/guides/text): `instructions`, text input and text output; responses are sent with `store: false`.
- [Web search](https://developers.openai.com/api/docs/guides/tools-web-search): hosted `web_search` is supplied only for explicitly selected web chat mode. URL citation annotations are preserved and shown as clickable source links.

The curated compatibility catalog is filtered by the account's `/v1/models` response after key validation. Access and quotas still depend on the user's account; errors never silently substitute a different model. Live and file processing have independently selected models. No monetary estimate is fabricated from token or audio usage.

## Continuous stream, coverage and fallback

- Audio is fsynced to disk first; the recorder passes each durable slice with its byte offset on the lecture timeline (`liveAppend(lectureId, pcm, offset)`, 48 bytes per ms). The 10-second WAVs are backup and playback only; new recordings store segments with status `audio` and no text.
- A *window* is a contiguous run of audio given to one realtime session. Before any network use it gets a durable `transcribe-range` task (`livePending`, never scheduled while live). Windows tile the recording: a new one opens after pause/resume, a discontinuity, a 55-minute renewal (at a turn boundary: right after a local commit, or at ≥300 ms silence with no speaking turn; forced at 59.5 minutes), or a reconnect after a failure (only at ≥300 ms of trailing silence; shorter pauses after 5 minutes; anywhere after 15 minutes, with exponential retry back-off up to 5 minutes).
- Server policy: each `speech_started`/`speech_stopped` item becomes a turn at `windowStart + audio_*_ms`. Local policy: LectureDesk's energy detector commits only when `shouldCommit(turnMs, trailingSilenceMs)` holds — ≥6 s & ≥500 ms pause, ≥20 s & ≥250 ms, ≥40 s & ≥100 ms, or 90 s — and sends `input_audio_buffer.clear` instead of a commit for turns with under 300 ms of speech, so silence is never committed.
- Only finished turns are stored, as `transcript_items` (`live:<windowId>:<item_id>`). The window's frontier is the end of the longest time-ordered prefix of finished turns. When a window closes (drain up to 45 s), the audio after the frontier not covered by finished turns becomes the task's `gaps`; the task is then `done` or queued for disk transcription. Late realtime results for a finalized window are ignored, so live and disk text never duplicate.
- Disk transcription (`transcribe-range`, also used when live transcription is off — `ensureCoverage` adds reconcile ranges at stop/recovery — and for crash leftovers, which wait until the recording is recovered) reads the PCM range, splits it only at pauses (target 180 s, maximum 285 s, quietest frame as a last resort), skips chunks with under 400 ms of speech and trims the rest to speech ± 300 ms. Each chunk result is an item keyed `range:<taskId>:<index>`, checkpointed so a resumed task never repeats a paid chunk.
- Lectures in Trash get no new AI work (queued tasks wait and resume after restore); `cancelLecture` stops scheduling for the lecture before it waits for running requests to settle.
- Translation and live notes consume finalized units in time order up to the coverage frontier (minimum over unfinished range tasks, open windows and untranscribed legacy segments). The original is assembled once the lecture is ready and no transcription task or window is outstanding; its timestamps mark speech turns.

## Language enforcement

Transcripts may contain only the selected lecture language plus English. Requests carry a localized description of the setting (for example "Wykład uniwersytecki po polsku.") plus the subject vocabulary; `languages` models get `[lecture, 'en']`. Every live and file result passes `checkTranscript`: text without letters and known silence hallucinations (subtitle credits such as "Продолжение следует", "Субтитры сделал DimaTorzok", "Thanks for watching", "Untertitel im Auftrag des ZDF für funk", Amara.org credits in any language, MBC news) are dropped without retry; runaway repetition, foreign scripts (CJK, Arabic, Hebrew, …; Greek allowed up to 20%), the wrong alphabet, other Latin-script languages (scored by distinctive stop words and letters for Polish, German, Spanish, French, Italian, Portuguese, Czech and Slovak: in Russian/Ukrainian lectures any identifiable non-English passage, at length ≥6 words; in Polish/English lectures passages of ≥8 words that clearly read as another language), Russian or Bulgarian passages in Ukrainian lectures (letters ы/э/ё/ъ or language-specific words), Ukrainian or Bulgarian in Russian lectures, and detected languages outside the allowed pair are rejected. Word runs with no language signals at all (technical terms, names, Latin anatomy) are kept. A rejected file result is retried once with a strict hint (lecture language only, no context); a rejected live turn becomes a strict disk gap. If the text is still wrong it is stored with status `rejected` and an error, hidden from the transcript, translation, notes and chat, and shown in the transcript as a warning row; the audio is preserved. The lecture language has no 'auto' value any more: libraries that used it are migrated to the interface language and must confirm the lecture language once before the next recording or import.

## Durability and costs

Audio is saved before `liveAppend`. Each realtime window owns a persistent range task, so a crash or disconnect can at most cause disk transcription of audio that was already streamed; it can never lose coverage. Disk transcription of a confirmed window costs nothing because its gaps are empty, and silent chunks are never sent. Legacy recordings and imported audio keep per-segment `transcribe` tasks, with the same silence guard and language checks. An interrupted or timed-out request might already have been billed by the provider; fallback cannot guarantee avoidance of that charge.

Queued API work runs with concurrency two. Transport failures retry indefinitely with exponential backoff capped at two minutes. Transient server/rate-limit errors retry at most five attempts, respecting Retry-After. Authentication, model/configuration, local-file errors and exhausted billing quotas remain visibly actionable. Removing the key pauses paid work; replacing it stops outstanding requests and resumes saved work. Cancellation aborts the request, prevents saving its result, and preserves source audio and immutable originals.

Task fingerprints cache identical text actions by source version, selected text, model, language, action instructions and format. Section processing and retranscription persist checkpoints. Already saved checkpoints and versions are reused on restart. There remains an unavoidable interruption window between a completed paid provider response and its first successful local database write.

Translation and live notes consume only finalized text in time order. Preliminary deltas never trigger AI analysis. Translation waits for the word threshold plus a sentence boundary, or the maximum wait, and flushes remaining text after transcription completes. A changed target language applies to subsequent text; translating the entire recording requires the explicit whole-recording action. Final notes map every source section and synthesize the section results through bounded requests. Originals and final notes wait for explicit recovery to finish an interrupted recording.

## Context and limitations

Chat builds a persistent Unicode FTS5 passage index from selected lectures' active versions, transcript segments, and selected/associated material pages. Scope filtering happens before a passage can enter an API request. Trashed lectures are excluded from implicit library and subject scopes. Retrieval includes prefix matching and common four-language study vocabulary, but does not provide general semantic or arbitrary cross-language vector search. A summary request maps all passages from all selected sources, rather than summarizing only the retrieved top passages.

Strict mode explicitly reports missing evidence. Knowledge and web modes request clearly distinguished additional knowledge. Source text is treated as untrusted data. The AI adapter exposes no application actions, command execution or filesystem tools to chat models.

Current live models provide no precise word alignment. LectureDesk timestamps mark the start of each speech turn (server turn detection, local voiced span, or the speech-trimmed disk chunk); legacy lectures keep segment timestamps. Whisper's returned segment timestamps and detected languages are preserved in operation usage data. Quality, real service latency, account access, long real sessions, and multilingual real recordings still require paid API validation with representative audio; mocked adapter tests do not establish those outcomes. In particular unverified: whether `gpt-4o-transcribe` accepts `semantic_vad` in a transcription session, manual commit while VAD is on (an error turns the tail into a disk gap), the exact `audio_start_ms` origin after renewals, and the local commit/RMS thresholds and language heuristics on real lecture audio.
